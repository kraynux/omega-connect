**Omega-connect** — связующее звено набора `omega-`: он находит установленные приложения omega (omega-serv, omega-fire, omega-jail…) на этой машине и на машинах вашей сети, показывает, что между ними связано, а что нет, и восстанавливает недостающее — всегда сначала показывая, что собирается сделать. После связывания приложения находят друг друга, даже когда omega-connect не запущен.

## 1. Видение и границы

Приложения omega созданы для совместной работы: журналы omega-serv читаются jail'ами omega-jail, баны fail2ban попадают в чёрный список omega-serv, а omega-fire всё это показывает. Но для этого файлы должны лежать в нужном месте, с нужными правами, а каждое приложение должно знать, где находятся остальные. Этим и занимается Omega-connect.

### Что делает Omega-connect

- Находит приложения omega на этой машине (домашняя папка, службы systemd, OpenRC или runit, `/srv`, реестр экземпляров omega-serv) и на других машинах, доступных по SSH с вашими ключами.
- Ведёт **реестр** всех приложений на всех машинах, с их версией и состоянием.
- Проверяет каждую **связь** между приложениями (журналы, читаемые jail'ами, мост к чёрному списку, защищённый список, файлы omega-jail в fail2ban, паспорта, общее пространство) и сообщает, что не в порядке.
- **Синхронизирует**: создаёт недостающие паспорта и подготавливает **общее пространство**, в котором приложения находят друг друга.
- **Исправляет**: каждое расхождение исправляет приложение, которому принадлежит файл; никогда не omega-connect вместо него.
- **Обновляет или переустанавливает** слишком старое или неправильно установленное приложение на машине в сети из его Release на GitHub (контрольная сумма проверяется).
- Действует на машине в сети **с вашего компьютера**: там ничего не нужно вводить, её пароль запрашивается один раз, ею самой.
- Составляет полный **отчёт** (текст, JSON или HTML-страница).

### Чего Omega-connect не делает

- Он не заменяет ни одно приложение: fail2ban, omega-fire, omega-jail и omega-serv сохраняют каждый свою роль.
- Он никогда не переписывает файл другого приложения.
- Он ничего не устанавливает на постоянной основе на машину в сети, чтобы её просканировать, и не оставляет работающих служб.
- Он никогда не запрашивает пароль SSH и никогда не видит ваш пароль администратора.

## 2. Установка

### Требования

- Linux, Python 3.10+.
- Для машин в сети: доступ по SSH с ключом и Python 3.10+ на этих машинах.
- Подключение к Интернету для зависимостей (и для обновлений с GitHub).

### Установка

Из папки, в которой находится архив:

```bash
tar -xzf omega-connect-0.1.0.tar.gz
cd omega-connect/
./install.sh
```

`install.sh`:

1. Создаёт виртуальное окружение `.venv` (неполное `.venv` откладывается в сторону и создаётся заново).
2. Устанавливает omega-lib (библиотеку набора, входящую в архив) и omega-connect.
3. Делает `omega-connect.sh` и `install.sh` исполняемыми.
4. Добавляет псевдоним `connect` в `~/.bashrc` и `~/.zshrc` (без дублирования).

Ни один шаг не требует прав администратора.

### Обновление

Из папки, которая СОДЕРЖИТ `omega-connect/` (никогда изнутри: `tar` создал бы вложенную папку), распакуйте новый архив поверх, затем снова запустите `install.sh`. Архив не содержит локальных данных (`var/`: реестр машин, настройки, экспорт): ничего из существующего не перезаписывается.

```bash
tar -xzf omega-connect-<version>.tar.gz
cd omega-connect/
./install.sh
```

## 3. Использование

### Интерактивный режим (TUI)

```bash
./omega-connect.sh
```

или, если псевдоним создан, `connect`.

Главное меню состоит из двух колонок:

| Управление | Обслуживание |
|---|---|
| **Реестр** — все приложения на всех машинах, их версия и состояние | **Исправить** — список всего, что не в порядке, и выбор |
| **Сканировать** — эта машина и добавление машин в сети | **Отчёт** — полный документ для экспорта |
| **Связи** — что связано, а что нет, с состоянием | **Настройки** — язык, темы, папки, очистка |
| **Синхронизация** — связать приложения на всех машинах | **Справка** — каждое меню, его назначение и подробности |
| **Панель** — общий обзор | **Выход** |

Типичный порядок работы: **Сканировать** (эта машина, затем ваши другие машины, предложенные на основе ваших профилей Unison, `~/.ssh/config` и `known_hosts`) → **Реестр** (обновить или переустановить старое приложение) → **Синхронизация** (отметить, затем синхронизировать) → **Связи** и **Панель**, чтобы увидеть результат → **Исправить**, если осталось расхождение.

Каждое действие сначала показывает свой план; ничего не запускается без вашего согласия. Для машины в сети интерфейс уступает место терминалу на время действия: машина сама запрашивает свой пароль, один раз.

#### Сочетания клавиш

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Перемещение между элементами |
| `Tab` / `Shift+Tab` | Перемещение между зонами экрана |
| `Enter` / `Пробел` | Активировать; отметить строку (Синхронизация) |
| `Esc` | Возврат на предыдущий экран |
| `a` | Справка |
| `s` | Настройки |
| `t` | Следующая тема |
| `r` | Перерисовать экран |
| `q` | Выход (с подтверждением) |
| `Ctrl+P` | Палитра команд: тема, снимок экрана, выход |

### Состояния

| Приложения | Связи |
|---|---|
| ● Связано — в общем пространстве, актуально | OK |
| ◐ Зарегистрировано — есть паспорт, но ещё нет в общем пространстве | требует исправления |
| ○ Обнаружено — без паспорта | требует исправления (блокирует) |
| ▲ Требует исправления — есть расхождение | отсутствует — связывать нечего |
| ◌ Старая версия — нужно обновить | проверка невозможна |
| ◇ Незавершённая установка — нужно переустановить | |
| ✕ Недоступно — машина больше не отвечает | |

### Языки интерфейса

Интерфейс доступен на 17 языках: французском, английском, испанском, португальском (Бразилия), итальянском, немецком, нидерландском, польском, русском, упрощённом китайском, вьетнамском, тайском, индонезийском, японском, корейском, хинди и арабском. Выбор делается в Настройках (« Langue / Language ») и применяется после перезапуска интерфейса; переменная `OMEGA_CONNECT_LANG` (например, `OMEGA_CONNECT_LANG=en ./omega-connect.sh`) задаёт язык на время одного сеанса. В текстовой консоли Linux (TTY) языки с нелатинской письменностью на время сеанса отображаются на английском. Командная строка остаётся на французском.

### Контакты и поддержка

Справка (клавиша `a`) содержит экран **Контакты и поддержка**: *Угостить кофе* (страница PayPal разработчика), *Связаться с поддержкой* (адрес почты и форма обратной связи сайта, показанные открытым текстом), *Зарегистрироваться как пользователь (анонимно)* и *Проверить обновления*. Регистрация добровольная, по умолчанию выключена и отправляется только один раз: она служит лишь для подсчёта пользователей и, по желанию, их континента или страны (закрытые списки, никакого произвольного текста). Отправляются случайно сгенерированный ключ, название программы (`omega-connect`) и её версия; никогда — имя, имя машины, адрес или настройки. IP-адрес не сохраняется в регистрациях, но, как и при любом посещении, проходит через проверки безопасности и журнал принимающего сервера. Отозвать регистрацию можно в любой момент на том же экране. Проверка обновлений лишь читает список опубликованных версий и никогда не выполняется без щелчка.

### Режим сценариев (CLI)

Любая команда запускает режим командной строки:

```bash
# Приложения этой машины или машины в сети (SSH с вашими ключами)
./omega-connect.sh scanner
./omega-connect.sh scanner moi@192.168.1.109

# Связать приложения этой машины или машины в сети
./omega-connect.sh synchroniser
./omega-connect.sh synchroniser --machine moi@192.168.1.109

# Обновить слишком старые приложения машины в сети (Release на GitHub)
./omega-connect.sh mettre-a-jour --machine moi@192.168.1.109

# Исправить: эта машина или машина в сети
./omega-connect.sh reparer --machine moi@192.168.1.109

# Состояние каждой связи и полный отчёт
./omega-connect.sh verifier
./omega-connect.sh rapport --format html --enregistrer
```

`--simulation` показывает план, ничего не запуская; `--oui` запускает без вопроса; `--toutes-machines` обрабатывает все известные машины, одну за другой.

## 4. Машины в сети

- **Подключение:** SSH только с вашими ключами; `~/.ssh/config` учитывается (псевдоним, порт, пользователь). Ключ, защищённый парольной фразой, должен быть загружен в SSH-агент.
- **Первое подключение:** прежде всего показывается отпечаток ключа машины; изменившийся ключ отвергается.
- **Сканирование:** программа отправляется в память, только для чтения; ничего не устанавливается и не записывается, пароль не запрашивается.
- **Действие** (синхронизировать, исправить, обновить): временная личная папка получает программу и, при необходимости, архивы; в конце она удаляется. Пароль администратора запрашивает сама машина, один раз.
- **Идентичность:** машина распознаётся по отпечатку своего системного идентификатора, а не по адресу: доступная через две сети, она остаётся одной машиной.
- **Обновления:** из Release на GitHub каждого приложения; контрольная сумма архива проверяется по `sha.txt` перед любой отправкой, затем повторно на машине. Каждое приложение устанавливается так, как описано в разделе «Обновление» его README.

## 5. Паспорт и общее пространство

- **Паспорт:** при установке каждое приложение omega записывает небольшой файл, который сообщает, что это за приложение (приложение, версия, идентификатор, машина). Доступен для чтения всем, никогда не изменяется другими учётными записями.
- **Общее пространство:** `/var/lib/omega-synchro`, отведённое группе `omega-synchro`, писать туда может только администратор. Omega-connect копирует туда паспорта и описание каждого приложения; приложения находят там друг друга, даже когда omega-connect не запущен.
- **Реестр общего пространства:** всё, что создаёт omega-connect, записывается в него; удаление отменяет только то, что там записано, а неизвестный файл никогда не удаляется.

## 6. Безопасность

- Никакого повышения прав при запуске: omega-connect работает под вашей учётной записью; sudo запрашивается для каждого действия отдельно, команда показывается заранее.
- Исправления выполняет приложение, которому принадлежит файл (omega-jail — для того, что он устанавливает в fail2ban, omega-serv — для прав своей папки `var/`, каждое приложение — для своего паспорта).
- Ни одно приложение не запускается, если оно может запросить пароль без терминала.
- Поиск никогда не следует по символическим ссылкам, не переходит в другую файловую систему и пропускает сетевые монтирования.
- Очистка папок экспорта и снимков экрана отказывается работать с системными, домашними папками и с папкой самого omega-connect.

## 7. Экспорт

- **Отчёт**: итог по всем машинам, точный список того, что осталось сделать, реестр, машины в сети, связи каждой машины, общее пространство. Текст, JSON или HTML-страница (тема на выбор).
- **Справка**: можно экспортировать в HTML-страницу.
- **Снимки экрана**: `Ctrl+P` → «Снимок экрана» (SVG).
- Папки по умолчанию: `var/exports/` и `var/screenshots/` в папке omega-connect, изменяются в Настройках.

## 8. Архитектура

Clean Architecture, как и в остальном наборе: `domain/` (чистые правила), `application/` (сценарии использования), `ports/`, `infrastructure/` (SSH, файлы, GitHub, буфер обмена), `interfaces/` (командная строка и интерфейс Textual), `app/` (сборка). Зависимости всегда направлены внутрь, это проверяет `import-linter`. Контракты, общие для приложений (паспорт, описание, общее пространство), находятся в `omega-lib`.

## 9. Тесты

```bash
source .venv/bin/activate
lint-imports        # проверяет правило зависимостей
pytest -q
ruff check src tests
mypy src
```

Тесты никогда не затрагивают настоящий `var/`, сеть или sudo: поддельный SSH, выполняемый локально, поддельный GitHub, временные папки.

## 10. Вне рамок

- Замена fail2ban, omega-fire или omega-jail.
- Непрерывное наблюдение (никакой постоянной службы).
- Первая установка приложения omega на машину в сети.
- Веб-панель мониторинга.
